Make your program talk to SurrealDB

Today you get a vertical slice: connect, write one record, read it back — the foundation everything in the explorer stands on.

Why this matters

Your mission is a DB-explorer TUI [mission]. An explorer is skin over a data layer — if the program can't talk to SurrealDB, there is nothing to explore. Your repo currently doesn't compile: #[tokio::main] is used but tokio isn't even in Cargo.toml, and Database/is_schema_exists are called but undefined. We'll fix the first properly today, and park the second until lesson 0002.

The three ideas you need

  1. The engine is a compile-time choice. The SDK is generic over its backing engine: Surreal::new::<Mem>(()) embeds an in-memory database inside your process — zero setup, perfect for development. Later, swapping to <Ws> points the same code at a real server.[1]
  2. Everything is async. Every SDK call returns a future, so a tokio runtime must exist. #[tokio::main] builds one under your main() — that's its whole job.[2]
  3. Serde is the bridge. Derive Serialize/Deserialize on a struct and records flow through it in both directions — typed queries, no string wrangling.[3]
Keep the connection cheat sheet open beside this lesson — it compresses everything below onto one page.

Do it now (~15 min)

  1. Add the missing dependencies. Run these in the project root: 
    cargo add tokio --features macros,rt-multi-thread
cargo add surrealdb --features kv-mem
cargo add serde --features derive

    kv-mem compiles the in-memory engine in — without the feature flag, Mem literally doesn't exist.[1] Check Cargo.toml: surrealdb now has features = ["kv-mem"].

  2. Replace all of src/main.rs with this. (Your old draft called functions that don't exist yet — we rebuild that idea properly next lesson.) 
    use serde::{Deserialize, Serialize};
use surrealdb::engine::local::Mem;
use surrealdb::Surreal;

#[derive(Debug, Serialize, Deserialize)]
struct Person {
    name: String,
    role: String,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // Engine chosen at compile time; runs inside this process.
    let db = Surreal::new::<Mem>(()).await?;
    db.use_ns("explorer").use_db("dev").await?;

    let made: Option<Person> = db
        .create(("person", "tobias"))
        .content(Person {
            name: "Tobias".into(),
            role: "learner".into(),
        })
        .await?;
    println!("created: {made:?}");

    let people: Vec<Person> = db.select("person").await?;
    println!("people: {people:?}");

    Ok(())
}
  3. Run it: cargo run

    Expected:

    created: Some(Person { name: "Tobias", role: "learner" })
people: [Person { name: "Tobias", role: "learner" }]

    If the compiler complains, read the error top-down and match it against the cheat sheet's error table before changing anything.

  4. Predict, then prove. Change ("person", "tobias") to just "person", keeping the Option<Person> annotation. Before compiling, say out loud whether this compiles, and what type the SDK would rather give you. Then run cargo check to settle it. Revert when done.
